# XiaoyuPostHub-Next

自建文件站与收件服务。文件内容分块加密后存放在 123 云盘，浏览器本地解密后交付；
同一个进程里还跑着一个 SMTP 收信服务和 Webmail。

**只收不发。** 没有外发通道——没有发信 SMTP、没有写信/回复/转发、没有草稿箱和发件箱。
如果你需要一个带发件的完整邮箱，这里不是。

```
浏览器 ──上传──▶ 服务端合并+加密 ──▶ 123 云盘（密文对象）
   ▲                                    │
   └────── 本地解密 ◀── 密文直连 ◀──────┘
```

存储侧不落明文，传输链路也不落明文。

## 快速开始

需要 Go 1.27+ 和 Node.js 20+。

```bash
./build.sh        # 构建前端并内嵌进二进制，产出 dist/xphd
./dist/xphd       # 直接跑，什么都不用配
```

打开 `http://127.0.0.1:8080/`，按引导页提示，填入启动日志里打印的一次性令牌完成初始化。

不想构建产物、只想看效果：

```bash
go run ./cmd/XiaoyuPostHub-Next   # 页面返回 503，API 正常（前端未内嵌）
```

启动日志会明确告诉你当前处于什么状态：

```
数据库: ./data/xph.db
数据目录: ./data（临时目录 ./data/tmp）
前端: 已内嵌进本二进制（无需外部目录）
加密: 就绪 KEK 版本=v1 块大小=1048576 字节 密钥信封=始终开启
存储后端: **未就绪**（尚未配置存储后端）
```

**首次初始化需要一次性令牌，本机也一样。** 一个还没初始化的实例对所有人开放，
任何人都可能是"第一个调用初始化接口的人"。早期版本对回环地址免令牌，但同机反向代理、
本机网页里的其它站点（DNS rebinding）都能借这个通道，所以现在任何来源都必须带令牌。
令牌只存在内存里，进程重启即更换；初始化完成后入口立即失效。

引导页要做三件事：创建首个管理员、生成主密钥、可选地填好 123 云盘凭据。
**保存即生效，无需重启。**

## 它做什么

### 文件

- **上传**：浏览器算明文 SHA-256 → 服务端查内容池实现秒传 → 未命中则分片上传
  （分片暂存临时盘，支持断点续传）→ 完成时合并、流式加密成密文临时文件 →
  整体写入 123 云盘。

  加密必须在全部收齐之后才做，因为 123 的创建接口要求提供密文的 MD5。

- **下载与预览**：服务端签发短时效票据和解密材料 → 浏览器直连存储拉**密文** →
  本地解密 → 校验完整性后交付。

- **去重**：相同明文只存一份，靠引用计数回收。对象名由 HMAC 派生，
  不泄露内容指纹。

### 邮件

在同一套加密内容池之上：

- **收信**：同进程 SMTP（默认 `:25`，监听地址可配，支持 STARTTLS），
  每 IP 连接数与速率限制。SPF 硬失败在 SMTP 阶段就拒收；RCPT 阶段校验域名、
  地址与配额——地址不存在返 550，配额满返 452。

- **Webmail**：收件箱阅读、星标、元数据搜索、**两段式**归档。
  HTML 正文在沙箱 iframe 里渲染，拦截远程图片。

- **复用加密管线**：正文打成 1 个加密容器，每个附件各 1 个加密对象，
  全部进同一个内容池。邮件存储配额与文件配额分开计算。

- **收件域名按用户组分配**：一个组可托管多个域名，同一个域名也能同时给多个组。
  配置入口在「用户组」页内（建组/改组时随表单提交），不另设页面。

## 核心设计

这几条决定了整个系统怎么写，值得先读。

### 1. 固定块大小是支点

XPH-Crypt v1 的文件布局：

```
Header(64 B, 明文) ‖ [CT₀‖Tag₁₆] [CT₁‖Tag₁₆] … [CTₙ₋₁‖Tag₁₆]

密文长度 = 64 + plainSize + 16 × N，N = ceil(plainSize / B)
```

块大小固定，意味着**明文偏移与密文偏移可以直接换算**。于是 Range 请求、音视频
seek、断点续传、预览全部可以直接作用在密文对象上，不用下载整个文件。

音频视频能边下边播、拖动进度条，就是靠这个——Service Worker 暴露一个本源的
"虚拟明文文件"，把浏览器的 Range 请求换算成密文区间、取回、解密、回 206。

代价是：**GCM 的 tag 覆盖整块，块不可截断**。任何读取都得先按块对齐算出完整密文
区间，读出整块解密后再裁剪两端。

文件头是自描述的，并作为 AAD 参与每块认证——篡改块大小或明文长度会直接认证失败，
而不是解析出错后产生难以归因的行为。

实现见 [`internal/xph`](internal/xph)，`format.go` 是容器格式，`crypt.go` 是分块加密。

### 2. 密钥信封：每个文件一把独立的内容密钥

```
主密钥 (KEK, 初始化时生成，base64 32 字节)
   └─ 包裹 ─▶ 每文件随机 DEK 的信封
                └─ 该文件全部内容块
```

内容密钥（DEK）**随机生成而非由文件盐派生**——这样密钥实体只有一个来源
（数据库里的信封），不必在文件里再放一份派生参数，也便于将来按 keyId 轮换 KEK。

主密钥派生出用途互不重叠的子密钥（通过 `info` 字符串，如 `xph/object-name`），
避免同一把主密钥在不同场景派生出可以互相替代的密钥。

主密钥被刻意收窄为"单密钥、仅初始化时写入"：支持多密钥轮换意味着改一行配置就能
让全部对象换一把保护伞，而误操作的代价是对象永久不可读。

### 3. SQLite 的写入是全局串行的——这是设计而非缺陷

围绕这一条做了五件事：

1. **读写分离双池**。WAL 下读不阻塞写、写不阻塞读，读池多连接并行。读池所有连接
   置 `query_only=1`，把"读路径误写"从偶发数据错乱变成确定性报错。

2. **写事务一律 `BEGIN IMMEDIATE`**。默认的延迟事务在"先读后写"时会尝试升级锁，
   失败时事务快照已作废、**不可重试**；提前声明写意图把它转化成排队，
   由 `busy_timeout` + 退避重试吸收。

3. **高频写入合批**。流量明细与日聚合走写后缓冲（2 秒或 4096 条刷一次）。
   额度判定不依赖它——额度走 `quota_counters`，始终同步写入，所以合批不会让
   任何限制失效。

4. **长流程不持有写事务**。上传与下载只在各自收尾处开短事务。

5. **STRICT 表 + 纯键值表 `WITHOUT ROWID`**。

前四条有对应断言在 `internal/store/concurrency_test.go`。

### 4. 没有迁移，只有终版结构

启动时执行内嵌的 `schema.sql`（全部 `CREATE ... IF NOT EXISTS`，可重复执行），
并把 `PRAGMA user_version` 戳到当前版本。代码里**没有版本分支、没有迁移脚本、
没有兼容旧结构的判断**——`user_version` 只作标记，不参与控制流。

> ⚠️ **改已有表结构必须重建库文件。** `IF NOT EXISTS` 只兜住缺失的对象，
> 不兜改过的定义：加一列之后旧库文件仍是老结构，且不会报错。
> 本项目不提供任何迁移途径。

## 配置

**只需要一个端口，其余全部可以留到前端初始化时填写。** 一个环境变量都不配也能跑。

只有启动引导相关的几项留在环境变量里——理由是同一条：它们都是"读取配置"这个
动作本身的前提。

| 环境变量 | 默认值 | 为什么不能入库 |
|---|---|---|
| `XPH_LISTEN` | `:8080` | 要在任何配置可读之前把服务挂起来 |
| `XPH_DB_PATH` | `./data/xph.db` | 它是"读配置"本身的前提，无法自举 |
| `XPH_DATA_DIR` / `XPH_TEMP_DIR` | `./data`、`./data/tmp` | 打开数据库前就要建目录、放密钥文件 |
| `XPH_MASTER_SECRET` | 空则自动生成 `./data/master.key`（0600） | 用于加密库里的敏感配置，不能和它保护的数据放一起 |
| `XPH_STATIC_DIR` | 空（用内嵌前端） | 要在打开 HTTP 之前决定页面从哪儿来 |

完整注释见 [.env.example](.env.example)。

业务配置全部在 SQLite 里，由管理后台读写（`GET/PUT /api/admin/settings`）。
SMTP 监听地址这类**不是**环境变量，而是入库的热生效设置。

| 关注点 | 做法 |
|---|---|
| 默认值 | 内置在代码里，数据库只存**覆盖项**。表为空也能跑 |
| 敏感值 | 用 master secret 派生密钥加密后入库（`enc:v1:`），展示时掩码 |
| 提交校验 | 写入侧校验类型、范围、枚举，非法值当场拒绝 |
| 热生效 | 快照 5 秒 TTL + 写入主动失效；存储后端按新配置重建并原子替换 |

**主密钥丢失或填错，已加密的对象将无法解密。** 请离线备份。

### 两个决定邮件可见性的设置

它们是**两个独立的键**，不是一个开关的两半：

| 键 | 分区 | 取值 | 默认 |
|---|---|---|---|
| `site.system_mode` | 站点 → 系统模式 | `both` / `files_only` | `both` |
| `mail.receive_enabled` | 邮件 → 启用收件 | 开 / 关 | **关** |

用户侧邮件功能要求**两者同时满足**，缺任一项时 `/api/mail/*` 一律返回 404
（表现为"这个站点没有邮件功能"，与从未部署过邮件的站点无区别，不泄露内部模式）。
侧栏的「邮件」入口用同一条判定。

管理端 `/api/admin/mail/*` 是另一条路：**只**看系统模式，关闭时返回 403。
管理员必须能在收件关闭时仍然进得去，否则出问题时连查看历史邮件的入口都没有。

## 开发

```bash
cd frontend
npm install
npm run dev          # http://127.0.0.1:5173，代理 /api 到 :8080
npm run typecheck    # vue-tsc，零错误才算过
npm run build        # 类型检查 + 打包
```

### 为什么必须同源

生产环境由后端吐出页面，而不是让前端单独部署到另一个域名：

- 票据走 URL 查询参数（跨域直链只能带 `Range` 一个请求头，自定义头会触发预检被拒）
- 内容密钥走同源响应体（进 URL 会落进 CDN 日志）
- Service Worker 只能注册在同源下

### 前端结构

```
frontend/src/
  api/           接口封装与类型定义（唯一的对外契约面）
  lib/           与界面无关的通用件
  composables/   跨页面复用的组合式函数
  stores/        跨路由存活的单例状态
  components/    自研组件；ui/ 是原子件，admin/ 是管理台专用
  views/         页面；admin/ 与 mail/ 是两个子目录
  delivery/      交付链路：下载、预览、分片上传
  crypto/        XPH-Crypt 的浏览器侧实现与 WebCrypto 封装
  sw.ts          Service Worker：把 Range 换算成密文区间并就地解密
```

三处值得一提的实现：

| 能力 | 做法 |
|---|---|
| 音视频实时解密播放 | Service Worker 暴露本源"虚拟明文文件"，把 Range 请求换算成密文区间、取回、解密、回 206 |
| 大文件交付 | 超 256 MiB 且浏览器支持 File System Access 时流式落盘；否则累积成 Blob。明文 SHA-256 用自实现的增量哈希，避免把整份内容读进内存 |
| 断点续传 | 会话标识记在浏览器本地，重传同一文件时先查会话是否仍有效。服务端刻意不提供"按校验码查会话"的接口——那会让校验码变成探测信道 |

**不依赖任何第三方 UI 库**，宽窄屏自适应、深浅色主题，解密/校验/分片上传都在浏览器里完成。

### 开发期校验

改动前后跑一遍，都是只读的：

```bash
# 后端
go build ./...
go vet ./...
gofmt -l ./cmd ./internal     # 应无输出
go test ./...

# 前端
cd frontend && npm run typecheck

# 上面全过之后，再出正式产物
./build.sh
```

`gofmt -l` 与 `npm run typecheck` 是两条硬门槛。前者防格式漂移，后者防类型漂移
（`tsconfig.json` 开了 `noUnusedLocals` / `noUnusedParameters`）。
`./build.sh` 内部也会跑类型检查，但它只保证产物能编出来，不保证你提交前的代码是干净的。

## 构建与发布

```bash
./build.sh                                  # 前端（含类型检查）+ 本机架构 → dist/xphd
./build.sh --all                            # 交叉编译矩阵，附 SHA256SUMS
GOOS=linux GOARCH=arm64 ./build.sh          # 指定单个目标
./build.sh --skip-frontend                  # 复用上一次 frontend/dist
./build.sh --only-frontend                  # 只构建前端
```

依次做四件事：

1. `npm ci`（有 lockfile 时）或 `npm install`
2. `npm run build`——**先跑 vue-tsc 类型检查再打包**，类型不过就不产出二进制
3. 把 `frontend/dist` 同步进 `internal/webui/dist`（`go:embed` 只能内嵌**包目录之内**的文件）
4. `CGO_ENABLED=0 go build -trimpath -ldflags "-s -w"`

**发布时只拷 `dist/xphd` 一个文件**，不会出现"二进制传上去了、dist 忘了拷"
这类只在打开页面时才暴露的事故。

关于"通用架构"：SQLite 走 `modernc.org/sqlite` 这个纯 Go 实现，不需要 cgo，
关掉 `CGO_ENABLED` 后产物是静态链接的，不依赖目标机的 glibc / musl 差异。
交叉编译出的 macOS 二进制**不能直接运行**（需要签名与公证）。

页面来源按优先级取：`XPH_STATIC_DIR` 指定的目录 → 二进制内嵌产物 → 503。
指定了目录却不指向有效目录时**不会**静默退回内嵌——那种隐式覆盖会让"我明明换了前端"
变成一个无法解释的现象。启动日志会写明走的是哪一条。

## 架构

```
cmd/XiaoyuPostHub-Next/     进程入口：自举、装配、启动自检、优雅关闭、后台维护
frontend/                   Vue 3 + Vite，无 UI 库
internal/config/            自举配置（端口、库路径、目录、master secret、前端目录覆盖）
internal/settings/          运行期配置：描述符注册表、校验、落库加密、快照与热生效
internal/secretbox/         敏感配置值的静态加密
internal/store/             SQLite：终版结构直建、仓储、并发访问层、运维操作
internal/backend/           存储后端抽象 + 123 云盘实现 + 运行时可替换的 Manager
internal/xph/               XPH-Crypt v1：分块 AES-GCM 容器格式与流式加解密/寻址
internal/auth/              口令哈希、会话、退避与身份解析
internal/service/           业务编排：上传、交付、文件树、分享、公告、配额、邮件收信、运维
internal/httpapi/           HTTP 接入层（文件站 API、Webmail API、管理后台）
internal/smtpd/             入站 SMTP 服务
internal/mailin/            入站邮件管线契约
internal/mailparse/         MIME 解析封装
internal/spf/               SPF 记录查询与最小机制求值
internal/perm/              权限位与预设用户组
internal/vpath/             逻辑路径规范化与比较
internal/clientip/          可信代理链下的客户端地址还原
internal/webui/             内嵌的前端构建产物
```

启动顺序刻意如此：**自举参数 → 数据库 → 配置 → 业务服务 → 监听端口**。
每个环节都必须能从"配置还没填"的状态恢复——配置存在数据库里，而数据库要先有
服务才能通过界面修改，所以启动路径不允许因为"某一项没配置"而退出。

## 运维

- **数据库备份**用 `POST /api/admin/database/backup`（在线一致快照，不阻塞读写），
  落盘在 `${XPH_DATA_DIR}/backup/`。**备份数据库时别忘了主密钥**，
  否则恢复出来的敏感配置解不开。

- **123 云盘 App 直接上传的对象是明文**，本系统读取时会因解密失败被静默过滤，
  用户界面上不可见。不要往同一目录混放。

- **对象的日期目录是上传日期**。秒传复用旧对象时不会迁移目录，因此按日期清理
  必须以引用计数为准，不能以目录名为准。

- 服务端任何"读明文"的功能（缩略图、全文索引、离线下载）都是加密的旁路，
  已在设计上排除。**新增功能时不要引入。**

- 归档可见性按状态划界：文件侧是**三段**——暂存（仅标记，引用与配额仍占用，可恢复）
  → 归档删除（释放引用与配额、远端未删）→ 存储删除（真删远端对象，记录保留）。
  用户侧只列出**暂存中**的批次，清除之后条目即从用户侧消失，此后只有管理端看得到。

## 已知限制

### 依赖上游平台行为、尚未实机确认

以下几项**在确认之前，相关能力按"未启用"处理**，不会静默降级成不安全的行为：

1. **CDN 缓存是否忽略查询参数**。若忽略，鉴权参数走 query 可能被缓存命中绕过。

2. **123 的 URL 鉴权是自校验还是回源到本程序**。决定能否做 IP 一致性校验。

3. **123 回源鉴权的参数必须手工配对。** 票据始终绑定签发者的网段（登录用户必然非空），
   而 123 的远程鉴权只能拼接回调 URL、设不了回源请求头。要在 123 面板「远程鉴权」里填：

   - **鉴权服务器地址**：`https://你的域名/api/cdn/auth` —— 不带任何参数
   - **自定义参数**：

     ```
     ① remote_addr  →  $remote_addr
     ② request_uri  →  $request_uri
     ```

   **两行的顺序不能反。** 直链持有者可以自己往 CDN 链接追加 `&remote_addr=6.6.6.6`，
   而服务端按"第一个同名参数"取值；`remote_addr` 排在前面才压得住它。

   漏配或写反的表现是**全部直链下载与连通性自检都报 HTTP 403**。排查方式：跑一次自检，
   看服务端日志 `httpapi: 回源鉴权拒绝：…`——`票据参数=未回传` 说明 `request_uri` 没配上，
   `访客地址=未透传` 说明 `remote_addr` 没带上。

4. **`create` 是否接受不同哈希与密文长度的组合**。当前实现固定使用密文哈希。

5. **后缀式 Range (`bytes=-N`) 在上游的可用性**。影响未做 faststart 的 MP4 预览。

### 设计上的取舍

- **没有发信能力**，且不会加。
- **主密钥不可更换**。误操作的代价是对象永久不可读，所以刻意收窄为仅初始化时写入。
- **改表结构要重建库**，没有迁移脚本。
- **需要 root 或 `CAP_NET_BIND_SERVICE` 才能监听 `:25`**。权限不足时进程不会退出，
  只记日志并每 5 秒重试。

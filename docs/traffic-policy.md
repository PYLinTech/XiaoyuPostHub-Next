# 全系统流量归属与优先级

## 判定顺序

1. 先检查访问权限：账号是否可用、访问者下载或预览权限、访客站点开关、分享访问方式、有效期与交付次数上限、分享下载或预览开关、对象状态。流量额度不授予访问权限。
2. 根据来源选择计费主体。其他用户或访客通过分享链接/取件码下载与预览：优先尝试分享创建者的每日分享额度。
3. 创建者剩余额度不足以覆盖本次票据的整笔预扣时，整笔转扣访问者的每日个人下载额度；访客使用访客组额度并按 IP 前缀聚合。不会把同一张票据拆成两个账单，也不会透支创建者的剩余额度。
4. 创建者访问自己的分享、自有文件、邮件正文/内嵌资源/附件，直接计入个人下载额度。个人下载额度适用身份的 `BypassQuota` 权限；明确配置的创建者分享额度不被访问者或创建者的该权限绕过。
5. 对外分享时仅在创建者和访问者两边均无法承担整笔预扣后返回额度不足。创建者额度为 0 时直接回退访问者；取消配置表示创建者分享额度不限，仍归创建者记账。

## 分享交付次数与历史记录

`maxDeliveries` 是每条分享的下载/预览交付计划上限，`0` 表示不限。解析分享页面、列目录不消耗该额度；下载或预览计划准备成功后原子计入一次，之后即使传输中断也占用一次。取件码核销同时受取件码自身的使用上限和分享交付次数上限约束。旧客户端仍可通过 `maxVisits` 字段读写同一上限。

分享访问/下载明细包含客户端 IP 与分享内路径，默认保留 365 天，可在“运维”设置中调整（设为 0 关闭自动清理）；维护任务按批次清理到期记录，删除分享时则级联删除其全部记录。概览中的浏览数是 `open`/`list`/旧 `view` 事件数，不是独立访客数；目录列表单独记为 `list`，避免重复计入一次 `open`。下载行标注 `server_measured`（服务端实测）或 `client_ack`（客户端回执）；客户端回执不构成文件已保存的独立证明。升级前无法判定来源的记录标为 `legacy_unknown`；旧客户端不发送 `completed` 的结算仍正常计费，但不会生成下载历史行。结算失败的结果会暂存到浏览器本地队列，应用下次启动、重新聚焦或网络恢复时重放；若本地存储不可用、票据到期前用户不再打开应用，或标签页在交付结果提交结算前被强制关闭，仍无法保证补结算；维护任务会按既有策略释放未结算票据的预扣额度。

## 管理配置

| 配额 | 作用 | 计量主体 |
| --- | --- | --- |
| `traffic.daily.share` | 每人每日分享流量；同一用户全部分享链接、目录内文件、取件码共用 | 分享创建者 |
| `traffic.daily.download` | 每人每日个人下载与预览；也承担创建者额度不足后的回退 | 登录用户，或访客 IP 前缀 |
| 存储、上传任务、邮件存储等配额 | 保持原有各自的资源限制；不是下载流量的替代额度 | 原有资源归属主体 |

用户组设置给组内每位用户各一份额度，**不是全组共用一个总池**。个人下载和分享额度为两个独立计数桶。所有日额度使用 UTC 自然日，UTC 00:00（中国标准时间 08:00）换日。组的资源调度优先级控制上传调度，不参与流量额度选择。

没有配额行表示不限，行值 0 表示该额度不可用；管理表单取消勾选会删除配额行，填写 0 会保留明确的零额度。个人下载中的 `BypassQuota` 豁免上限判定但仍记账；分享优先顺序不会因访问者具有该权限而改变。新分享配额默认无配置，不自动继承创建者的个人下载上限。

## 各通道的统一行为

| 访问路径 | 计费规则 |
| --- | --- |
| 分享链接、目录分享内文件、取件码：下载与预览 | 创建者分享额度 → 访问者个人额度 |
| 创建者本人通过其分享链接/取件码访问 | 个人下载额度 |
| 自有文件、邮件正文与附件的文件交付 | 个人下载额度 |
| CDN 直链、中转加密、中转解密、原生播放器、兼容播放器、Service Worker | 保留来源所选的同一计费规则；改变通道不改变承担者 |
| 分享说明、目录列表、取件码查看及 HEAD 探测 | 不产生文件交付预扣；HEAD 不增加票据使用次数 |
| 上传与邮件收发统计、存储自检探针 | 保持各自原有统计/资源限制；零预扣自检不占下载额度 |

下载与预览共用日流量，不另设可绕过的预览池。配额与预扣沿用实际加密对象的密文字节（含文件头与块认证开销），报表同时保留明文字节，不能用明文文件大小推断可用密文额度。

## 预扣、结算与退款

创建者预扣失败的原子条件更新不会写入计数；访问者回退预扣、票据创建在同一写事务完成。只有额度不足允许回退，数据库故障、授权失败及分享失效均按原错误拒绝。并发多个链接或取件码不会击穿同一创建者的分享总额。

每张新票据持久化实际额度桶、带日期的计数键、承担用户与用户组快照，同时保留实际访问者、来源 IP、分享标识、取件码及资源路径。票据仍只授权原访问者使用，承担者不会因支付流量而获得使用该票据的权限。

- 中转解密由服务端按已有真实用量折算结算；差额退回原计费桶。
- 客户端可自行结算的 CDN 直链/中转加密继续按整笔预扣结算，防止不可信上报骗取退款。
- 准备失败、取消、取件码核销失败、过期维护等退款路径都使用票据冻结的计数键；跨日、用户换组、分享删除不会改退款归属。
- 新限额及换组在下一张票据签发时读取当前配置，当日既有用量不会因换组重置。已签票据不在每个 Range 请求重选计费主体。
- 升级前的票据没有新快照，保持原有访问者的个人桶结算/退款；不对历史流量猜测或回溯重分配。

## 报表

流量明细分别展示“访问者 / 访问者组”和“流量承担者 / 计费组 / 额度来源”，支持按承担用户编号筛选。日聚合只给实际承担者累计一次，防止同一笔分享访问同时计到创建者与访问者。明细与日聚合仍由缓冲批量写入，实时限制始终由同步额度计数器判定。
